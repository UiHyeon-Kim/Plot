# 기술 결정 기록 (ADR)

아키텍처·라이브러리 선택처럼 나중에 "왜 이렇게 했는지"를 설명해야 하는 결정을 남긴다. 코드 리뷰나
면접에서 "왜 이 구조를 택했나요?" 질문에 이 문서를 근거로 답할 수 있게 하는 것이 목적이다.

## 언제 쓰나
- 여러 대안 중 하나를 골랐고, 그 이유가 코드만 봐서는 드러나지 않을 때.
- 나중에 뒤집을 수도 있는 결정이라 "그때는 왜 이걸 골랐는지" 맥락이 필요할 때.
- 반대로 사소한 구현 디테일(변수명, 파일 위치)은 ADR 대상이 아니다 — 코드가 스스로 설명한다.

## 파일명 규칙
`NNNN-<결정을-서술하는-제목>.md` — 제목 자체가 결정 내용을 담아야 한다.
- 좋은 예: `0002-hilt-koin-대신-채택.md`
- 나쁜 예: `0002-di-adr.md` (파일명만 보고 뭘 결정했는지 알 수 없음)

## 파일 구조
```markdown
# NNNN. <결정 제목>

- 상태: 채택 / 폐기 / 대체됨 (0005로 대체 등)
- 날짜: YYYY-MM-DD

## Context
왜 이 결정이 필요했나. 어떤 제약/요구가 있었나.

## Decision
무엇을 선택했나.

## Alternatives considered
다른 선택지와, 왜 그걸 고르지 않았나.

## Trade-off
이 선택으로 포기한 것, 나중에 재검토가 필요한 조건.
```
